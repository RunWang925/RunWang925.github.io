## 四、自动化部署配置（最终稳定版）

19. 解决依赖冲突（修正 ESM 错误）

#### 步骤 1：修改`package.json`文件

用 VS Code 打开`E:\PeiqIBlog\hexoblog\package.json`，在`dependencies`字段后添加`resolutions`（锁定兼容版本）：

json

```JSON
{"name": "hexo-site","version": "0.0.0","private": true,"scripts": {"build": "hexo generate","clean": "hexo clean","deploy": "hexo deploy","server": "hexo server"},"hexo": {"version": "8.0.0"},"dependencies": {"hexo": "^8.0.0","hexo-generator-archive": "^2.0.0","hexo-generator-category": "^2.0.0","hexo-generator-index": "^4.0.0","hexo-generator-tag": "^2.0.0","hexo-renderer-ejs": "^2.0.0","hexo-renderer-marked": "^7.0.0","hexo-renderer-stylus": "^3.0.1","hexo-server": "^3.0.0","hexo-theme-landscape": "^1.0.0"},"resolutions": {"strip-ansi": "6.0.1"  # 关键：锁定兼容版本，避免ERR_REQUIRE_ESM错误
  }}
```

#### 步骤 2：安装依赖工具并更新

bash

```Bash
# 1. 全局安装工具（让resolutions配置生效）npm install -g npm-force-resolutions

# 2. 更新依赖（自动下载strip-ansi@6.0.1）npm install
```

20. 创建 GitHub Actions 工作流文件

#### 步骤 1：创建工作流目录

bash

```Bash
# 在hexoblog目录创建隐藏文件夹与子目录（自动创建，无需手动建）mkdir -p .github/workflows
```

#### 步骤 2：编写工作流配置文件

用 VS Code 创建`E:\PeiqIBlog\hexoblog\.github\workflows\hexo-deploy.yml`，粘贴以下内容（已适配用户信息）：

yaml

```YAML
name: Hexo Auto Deploy (RunWang925)

# 触发条件：推送到main分支时执行on:push:branches:- main

jobs:deploy:runs-on: ubuntu-latest  # 使用Ubuntu系统运行steps:# 步骤1：拉取GitHub main分支源码- name: Checkout main branch
        uses: actions/checkout@v4
        with:ref: main
          fetch-depth: 0  # 拉取所有历史记录，避免构建错误# 步骤2：安装Node.js（与本地版本一致：22.x）- name: Set up Node.js
        uses: actions/setup-node@v4
        with:node-version: '22.x'cache: 'npm'  # 缓存依赖，加快构建速度# 步骤3：安装Hexo依赖- name: Install Hexo dependencies
        run: |
          npm install -g hexo-cli
          npm install# 步骤4：清空并生成静态文件- name: Generate static files
        run: hexo clean && hexo generate

      # 步骤5：部署到gh-pages分支- name: Deploy to gh-pages branch
        uses: peaceiris/actions-gh-pages@v4
        with:github_token: ${{ secrets.HEXO_DEPLOY_TOKEN }}  # 使用PAT令牌（后续配置）publish_branch: gh-pages  # 部署目标分支publish_dir: ./public     # Hexo静态文件目录user_name: 'github-actions[bot]'user_email: 'github-actions[bot]@users.noreply.github.com'
```

21. 配置 GitHub 个人访问令牌（PAT）

#### 步骤 1：生成 PAT

1. 登录 GitHub → 右上角头像 →「Settings」→ 底部「Developer settings」→「Personal access tokens」→「Tokens (classic)」→「Generate new token」
2. 配置项：
   1. Note：`Hexo Deploy Token (RunWang925)`
   2. Expiration：`No expiration`（永不过期）
   3. Scopes：勾选「repo」下所有选项（全选）
3. 点击「Generate token」→ **立即复制令牌**（仅显示一次，存到记事本）

#### 步骤 2：添加令牌到仓库 Secrets

1. 打开仓库：`https://github.com/RunWang925/RunWang925.github.io`
2. 「Settings」→「Secrets and variables」→「Actions」→「New repository secret」
3. 配置：
   1. Name：`HEXO_DEPLOY_TOKEN`（必须完全一致，否则工作流报错）
   2. Secret：粘贴刚才复制的 PAT 令牌
4. 点击「Add secret」→ 完成配置
5. 推送工作流配置到 GitHub

bash

```Bash
# 1. 添加配置文件到暂存区git add .# 2. 提交（备注清晰）git commit -m "config: 添加GitHub Actions自动部署配置（修复依赖冲突+PAT令牌）"# 3. 推送git push
```

6. 验证 Actions 工作流
7. 打开仓库「Actions」标签页：`https://github.com/RunWang925/RunWang925.github.io/actions`
8. 看到「Hexo Auto Deploy (RunWang925)」工作流 → 状态为「正在运行」（黄色）
9. 等待 1-2 分钟，状态变为「成功」（绿色对勾）→ 自动化部署配置完成

## 七、历史错误复盘与避坑指南

20. 分支名不匹配（最常见错误）

* 错误提示：`fatal: the requested upstream branch 'origin/main' does not exist`
* 原因：本地分支是 master，远程是 main
* 解决方案：`git branch -m master main`（修改本地分支名）

21. 依赖冲突（ESM 错误）

* 错误提示：`Error [ERR_REQUIRE_ESM]: require() of ES Module ... strip-ansi/index.js`
* 原因：strip-ansi 新版本与 Hexo 不兼容
* 解决方案：在`package.json`添加`resolutions: {"strip-ansi": "6.0.1"}`，并执行`npm install`

22. 权限错误（403 Permission denied）

* 错误提示：`remote: Permission to RunWang925/... denied to github-actions[bot]`
* 原因：默认 GITHUB\_TOKEN 权限不足
* 解决方案：配置 PAT 令牌，在工作流中使用`secrets.HEXO_DEPLOY_TOKEN`

23. 推送冲突（failed to push some refs）

* 错误提示：`error: failed to push some refs to 'https://github.com/...'`
* 原因：GitHub 仓库有本地没有的文件（如 README）
* 解决方案：`git pull --rebase origin main`（同步远程文件后再推送）

24. 本地预览空白页

* 原因：缓存或生成文件错误
* 解决方案：`hexo clean && hexo generate && hexo s`（清空→生成→预览）
